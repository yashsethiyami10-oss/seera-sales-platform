**Content:**

> **Historical source citation only (recorded during source audit) — NOT a live commercial
> value. Per FR-001/FR-002, current pricing must always be resolved from the Product Catalog
> API, never from this figure.** The table below documents what two source documents said during
> original research; it is retained as an audit trail, not as AI-answerable content.

| Source | Cool Water 1 L MRP | Cool Water 5 L MRP |
|---|---|---|
| `MUV_Product_Chart_with_USP (1)(1).pdf`, rows 3–4 | ₹165 | ₹725 |
| `MUV_Liquid_Detergent_Final_Production_SOP_v2-1.docx`, "Finished Product Details" | ₹155 *(generic figure, not variant-specific)* | ₹699 *(generic figure, not variant-specific)* |

This discrepancy was already flagged in the codebase prior to this package's creation — see the
comment in `lib/knowledge-factory/conflict-service.ts:11-18` (this session's own Sprint 3 work),
which references *"the Liquid Detergent Cool Water pricing conflict found when the new SOP was
verified."* This package independently re-confirmed the exact numbers on both sides.

**Resolution status:** UNRESOLVED as a source-document/audit question. Per this codebase's own
Knowledge Factory governance principle (`KnowledgeConflict` model, Sprint 3 of the MUV AI
Engineering Execution program) and this task's own constitution ("the decision itself remains a
human one... never guess"), this package does **not** pick one number as the historically
"correct" source figure. A Founder decision is still open on that narrow historical question: is
the Product Chart's differentiated Cool Water pricing (₹165/₹725) the figure that was current
when each source was written, with the SOP's generic figure simply not yet updated to reflect it
— or is the SOP's uniform pricing (₹155/₹699) correct, with the Product Chart containing a
stale/incorrect row? Either is plausible; neither is assumed here.

**Effect of FR-001/FR-002 on this conflict:** as of 2026-07-31, this open question no longer
blocks any AI-facing pricing answer. Per the Commercial/Knowledge Separation, no variant's price
— Cool Water included — is ever answered from this package's content any more; all pricing is
always resolved live from the Product Catalog API (see `LIVE_DATA_MAPPING.md`). This record
therefore remains OPEN purely as a historical/audit matter (which source document was accurate
at the time it was written), not as a live-answer blocker.

**Recommended next step:** if and when the Founder wants the historical question itself
resolved (e.g. for internal record-keeping), this conflict can be recorded as a real
`KnowledgeConflict` row via the platform's own `lib/knowledge-factory/conflict-service.ts`
(`createConflict`/`resolveConflict`). It has no bearing on `KO-LD-VAR-003`'s pricing field, which
no longer stores a pricing value at all. This package does not perform that database write
itself, since the Output Structure for this task specifies file deliverables only — flagged here
as a deliberate scope boundary, not an oversight.
